# مسیر پروژه‌محور C# و ASP.NET Core

آموزش فارسی برای ساخت بک‌اند قابل نگهداری، از اولین برنامهٔ C# تا یک سرویس قابل استقرار با PostgreSQL.
کد، نام کلاس‌ها و نام پوشه‌ها انگلیسی‌اند؛ توضیحات و تمرین‌ها فارسی هستند.

## این دوره تو را به چه سطحی می‌رساند؟

هدف این مسیر، توانایی ساخت و نگه‌داری بک‌اند با C#، ASP.NET Core و PostgreSQL است. اگر نمونه‌ها را اجرا، تمرین‌ها را مستقل حل و پروژهٔ نهایی را بدون کپی مستقیم پیاده کنی، می‌تواند پایهٔ جدی برای کار حرفه‌ای باشد. خواندن ۹۰ درس یا سبزشدن تست‌های نمونهٔ آماده به‌تنهایی نشان‌دهندهٔ مهارت حرفه‌ای یا سطح شغلی مشخص نیست؛ مدت ثابت و تضمین استخدام هم نداریم.

برای سنجش نتیجه، باید بتوانی یک نیاز تازه را به API و مدل داده تبدیل کنی، مجوز درست اعمال کنی، تست شکست بنویسی، خطای ناآشنا را پیدا کنی و تغییرت را با دلیل توضیح بدهی. تجربهٔ کار تیمی، بازخورد code review و نگه‌داری پروژهٔ واقعی این توانایی‌ها را کامل می‌کنند. محدودهٔ دوره بک‌اند وب است؛ آموزش همهٔ شاخه‌های .NET مانند برنامه‌های دسکتاپ و موبایل را هدف نمی‌گیرد.

## پیش‌نیازهای شروع

| مورد | انتظار پیش از شروع |
| --- | --- |
| کار با کامپیوتر | ساخت پوشه، بازکردن و ویرایش فایل و پیدا کردن مسیر آن را بلد باشی |
| خط فرمان | بتوانی ترمینال را باز کنی و فرمان را وارد کنی؛ فرمان‌های لازم در درس ۱ توضیح داده می‌شوند |
| منطق پایهٔ برنامه‌نویسی | آشنایی با متغیر، شرط، حلقه و تابع کمک زیادی می‌کند؛ درس‌های آغازین آن‌ها را در C# آموزش می‌دهند |
| خواندن خطا و مستندات | بتوانی متن انگلیسی خطا را بخوانی یا با کمک ترجمه دنبال کنی؛ انگلیسی پیشرفته شرط شروع نیست |
| زمان تمرین | برای اجرا، تغییر کد و رفع خطا وقت بگذاری؛ خواندن متن بدون تمرین معیار عبور نیست |

اگر قبلاً با C++، Java یا زبان دیگری کار کرده‌ای، می‌توانی از درس ۱ شروع کنی. C#، ASP.NET Core، SQL، طراحی معماری، JWT و Docker دانش قبلیِ الزامی نیستند و در مسیر آموزش داده می‌شوند. اگر هیچ تجربهٔ برنامه‌نویسی نداری، ابتدا با تمرین‌های کوچک متغیر، if، حلقه و تابع آشنا شو یا برای درس‌های ۲ تا ۶ زمان بیشتری بگذار؛ پیش از عبور باید بتوانی خروجی چند خط کد ساده را پیش‌بینی کنی.

برای شروع، مدرک دانشگاهی، ریاضی پیشرفته، تجربهٔ فرانت‌اند یا خرید سرور و دامنه لازم نیست. C++ و Qt پیش‌زمینهٔ مفیدی هستند، ولی مدیریت حافظه، reference و async در C# را از روی شباهت ظاهری با آن‌ها فرض نکن.

## ابزارها را در چه مرحله‌ای آماده کنم؟

| مرحله | ابزار و دسترسی لازم | راهنما |
| --- | --- | --- |
| شروع C# | کامپیوتر، SDK .NET 10، ویرایشگر و دسترسی نصب ابزار | [درس ۱](lessons/01-foundations/001-environment/README.md) |
| دریافت و نگه‌داری تمرین | Git برای clone و ثبت تغییر؛ دریافت ZIP هم برای شروع ممکن است | [تمرین Git](handbook/git-practice.md) |
| بررسی‌های خودکار دوره | Python 3 برای اجرای scriptها؛ یادگیری زبان Python شرط این دوره نیست | فرمان‌های بررسی پایین همین صفحه |
| دیتابیس، از درس ۳۵ | PostgreSQL 18 تمرینی؛ psql برای بخش‌هایی از بازرسی و تست‌های کامل داده/امنیت | [آزمایشگاه PostgreSQL](handbook/postgresql-lab.md) |
| تست کانتینری و استقرار محلی | Docker فعال با Linux containers؛ برای Testcontainers درس ۷۴ و آزمایش‌های Docker، Redis، TLS و بازیابی | [درس ۷۴](lessons/07-testing/074-database-tests/README.md) و [بخش عملیات](lessons/08-production/README.md) |
| مکمل‌های JWT/OIDC | HTTPS معتبر محلی؛ اتصال دستی OIDC به IdP واقعی به ثبت client و کاربر تمرینی نزد آن provider نیاز دارد | [مکمل OIDC](lessons/06-security/064b-oidc/README.md) |

برای نصب SDK و دریافت اولیهٔ packageهای NuGet و imageهای Docker، دسترسی شبکه لازم است؛ مرحلهٔ نصب هر بخش را همان موقع انجام بده. راهنمای آغاز برای Windows و PowerShell نوشته شده و نمونه‌ها در CI روی Windows و Linux بررسی می‌شوند؛ دانش قبلی Linux شرط شروع نیست. فقط runtime به جای SDK کافی نیست.

حساب سرویس خارجی برای تست‌های خودکار JWT/OIDC لازم نیست؛ ارائه‌دهندهٔ کنترل‌شده داخل پروژهٔ تست استفاده می‌شود. حساب provider واقعی مربوط به تمرین دستی جداگانه است. داده و credential تمرین‌ها را در محیط اختصاصی آزمایشگاهی نگه دار.

## چگونه بفهمم برای ادامه آماده‌ام؟

پس از درس‌های آغازین، باید بتوانی پروژه را خودت بسازی و اجرا کنی، یک شرط یا محاسبه را تغییر بدهی، یک خطای ساده را از پیام آن پیدا کنی و نتیجه را توضیح بدهی. اگر هنوز این کارها وابسته به کپی پاسخ‌اند، همان مرحله را با دادهٔ تازه تکرار کن. از [روش یادگیری](handbook/learning-method.md) و [دفتر پیشرفت](PROGRESS.md) برای ثبت شاهد استفاده کن.

برای تبدیل آموزش به تجربهٔ حرفه‌ای، پس از پروژهٔ نهایی یک پروژهٔ متفاوت با نیازمندی‌های خودت بساز؛ مثلاً مدیریت تجهیزات یا درخواست خدمات. آن را با دیتابیس، مجوز، تست، CI، روش استقرار و بازیابی تحویل بده، از فرد دیگری review بگیر و دست‌کم یک تغییر نیازمندی را بدون بازنویسی کامل انجام بده. توانایی ساخت، توضیح، عیب‌یابی و نگه‌داری این پروژه معیار بهتری از تعداد درس‌های خوانده‌شده است.

## وضعیت واقعی محتوا

این نسخه شامل هر نه بخش کامل در [GitHub](https://github.com/k1nosraty/dotnet-backend-roadmap) است: ۹۰ درس نوشته شده، ۸۹ نمونهٔ مستقل C# و ۱۶ پروژهٔ مجزای تست آماده شده است.
[پروژهٔ نهایی ServiceDesk](lessons/09-capstone/README.md) قرارداد، اجرای مستقل، تست، TLS و بازیابی دارد.
ساخت و بررسی رفتار نمونه‌ها در workflow «Check course» روی Windows و Linux در GitHub اجرا می‌شود؛ نتیجهٔ هر commit را در تب Actions ببین.
شانزده پروژهٔ مجزای xUnit در پوشهٔ tests وجود دارد؛ در شمار نمونه‌های اجرایی بالا شمرده نشده‌اند.
فرمان ساخت، سناریوهای بررسی و اسکریپت smoke در بسته وجود دارند.

```powershell
python scripts/check_content.py
python scripts/smoke.py
python scripts/web_smoke.py
python scripts/controller_smoke.py
python scripts/domain_smoke.py
python scripts/architecture_smoke.py
python scripts/architecture_next_smoke.py
python scripts/architecture_final_smoke.py
# برای نمونه‌های PostgreSQL پس از آماده‌سازی server و SUPPORTDESK_PG:
python scripts/postgres_smoke.py
python scripts/ef_smoke.py
python scripts/security_smoke.py
python scripts/security_next_smoke.py
python scripts/security_final_smoke.py
# تست‌های xUnit و WAF؛ برای اجرای PostgreSQL کانتینری، --with-docker اضافه کن:
python scripts/testing_smoke.py
python scripts/testing_next_smoke.py
python scripts/production_smoke.py
# Docker واقعی برای image و TLS:
python scripts/production_docker_smoke.py
python scripts/operations_smoke.py
python scripts/capstone_smoke.py
# Docker واقعی برای تست نهایی و تحویل TLS و restore:
python scripts/capstone_smoke.py --docker-only
python scripts/capstone_delivery.py
# تست واقعی Redis/PostgreSQL و بازیابی: --with-docker اضافه کن.
```

اسکریپت‌های بررسی به Python 3 نیاز دارند؛ اسکریپت‌های smoke به SDK 10 هم نیاز دارند. postgres_smoke به PostgreSQL واقعی و متغیر SUPPORTDESK_PG نیز نیاز دارد. ef_smoke برای بخش API علاوه بر این‌ها psql می‌خواهد؛ متغیرهای اتصال تست در README نمونهٔ تحویل توضیح داده شده‌اند. security_smoke و security_next_smoke و security_final_smoke در حالت کامل PostgreSQL و psql و متغیرهای اتصال تست مطابق فهرست بخش امنیت می‌خواهند. اجرای دستی درس‌های دیتابیس نیز PostgreSQL و اتصال تنظیم‌شده می‌خواهد.

## مبنای فنی

- .NET 10 و ASP.NET Core؛ SDK نسخهٔ 10 لازم است.
- PostgreSQL در بخش دیتابیس.
- ابتدا امکانات استاندارد .NET؛ کتابخانهٔ خارجی هنگام مواجهه با مسئله معرفی می‌شود.
- راه‌اندازی درس اول برای Windows و PowerShell نوشته شده است.
- مبنای نسخهٔ .NET در ۲۰۲۶/۱۰/۱۴ با منابع رسمی بررسی شده است.
- [دانلود رسمی .NET 10](https://dotnet.microsoft.com/en-us/download/dotnet/10.0)

## مهارت خروجی

بتوانی نیازمندی را به قرارداد API، قواعد کسب‌وکار و مدل داده تبدیل کنی.
بتوانی مرز controller، service و data access را توضیح بدهی.
بتوانی یک خطا را با تست و لاگ پیدا کنی، اصلاح کنی و از تکرارش جلوگیری کنی.
بتوانی دربارهٔ هزینهٔ هر dependency و abstraction تصمیم بگیری.

تمام کردن متن‌ها معادل تجربهٔ حرفه‌ای نیست؛ معیار این دوره توانایی ساخت و دفاع از تصمیم‌های فنی است.

[ممیزی کیفیت کل دوره](AUDIT-90.md) دامنه، اصلاح‌ها و محدودیت‌های مرور جدید را ثبت می‌کند. [ممیزی تاریخی تا درس ۶۰](AUDIT-60.md) محدودهٔ تأیید، مرور هر درس، تقویت تست‌ها و شواهد CI را ثبت می‌کند. [گزارش تاریخی درس‌های ۱ تا ۳۴](AUDIT.md) نیز حفظ شده است.
