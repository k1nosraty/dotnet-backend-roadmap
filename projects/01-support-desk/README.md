# پروژهٔ اول: SupportDesk CLI

در این پروژه ابزار کنسولی برای درخواست‌های پشتیبانی یک تیم IT می‌سازیم.
این دامنه کمک می‌کند قواعد، وضعیت‌ها و گزارش‌گیری را پیش از ورود به HTTP یاد بگیریم.

## نیازمندی نهایی پروژه

- ثبت درخواست با شناسه، عنوان، اولویت و وضعیت.
- فهرست درخواست‌ها و جست‌وجو با شناسه.
- تغییر وضعیت با رعایت قواعد مجاز.
- گزارش تعداد درخواست‌های باز و بسته.
- ذخیره در JSON و بارگذاری در اجرای بعد.
- مدیریت ورودی خراب، فایل خراب و خروج برنامه.

## مراحل تحویل

| مرحله | درس | خروجی قابل بررسی |
| --- | --- | --- |
| خلاصهٔ ثابت | ۰۰۲ | جمع و درصد صحیح |
| ورودی معتبر | ۰۰۳ | پذیرش مقدار صحیح و رد ورودی خراب |
| منو و متد | ۰۰۴، ۰۰۵ | چند عملیات بدون تکرار کد |
| مجموعه و مدل | ۰۰۶ تا ۰۰۸ | ثبت چند درخواست و lookup |
| ذخیره و گزارش | ۰۰۹ تا ۰۱۲ | persistence و LINQ و رفتار لغو |
| طراحی قابل تغییر | ۰۱۳ تا ۰۲۲ | تفکیک UI و use case و persistence |

## قواعد کسب‌وکار پایه

عنوان پس از حذف فاصلهٔ ابتدا و انتها بین ۳ و ۱۲۰ کاراکتر است.
شناسه در همان مخزن یکتا و مثبت است.
اولویت یکی از Low، Normal و High است.
وضعیت یکی از Open، InProgress و Closed است.
در این نسخه مسیر مجاز Open به InProgress و InProgress به Closed است.
بازگشایی درخواست در این نسخه وجود ندارد؛ افزودن آن تمرین تغییر نیازمندی خواهد بود.

## بررسی نهایی

- ثبت سه درخواست، بستن یکی و دیدن گزارش درست.
- راه‌اندازی مجدد و باقی ماندن داده.
- جست‌وجوی شناسهٔ ناموجود بدون crash.
- فایل JSON خراب با پیام واضح و بدون پاک کردن خودکار داده.
- توضیح اینکه کدام کلاس مسئول ورودی و کدام مسئول ذخیره است.

بخش Foundation با نمونهٔ یکپارچهٔ درس ۰۱۲ کامل شده است: مدل، وضعیت، گزارش و JSON asynchronous دارد.
تمرین‌های find و rename را باید مستقل اضافه کنی؛ نسخهٔ کامل پروژهٔ CLI و بازآرایی آن تا درس ۰۲۲ ادامه دارد.
