## ارزیابی مستقل: SupportDesk Foundation

در exercises پروژه‌ای تازه بساز؛ از روی نمونهٔ آخر کپی کامل نکن.
می‌توانی برای یادآوری syntax به درس‌ها برگردی.

نیازمندی‌ها:

1. ثبت Ticket با عنوان معتبر و شناسهٔ مثبت یکتا.
2. فهرست مرتب، find و rename با شناسه.
3. وضعیت Open به InProgress به Closed و رد مسیر غیرمجاز.
4. گزارش همهٔ وضعیت‌ها، شامل تعداد صفر.
5. ذخیرهٔ JSON و بازیابی پس از restart.
6. رد JSON خراب، شناسهٔ تکراری و enum نامعتبر بدون بازنویسی فایل.
7. I/O با await و token لغو؛ توضیح محدودیت input کنسول.
8. جداسازی فایل مدل، storage و برنامهٔ تعاملی.
9. README با روش اجرا، قرارداد داده و سناریوهای بررسی.

قرارداد این ارزیابی تک‌process و دادهٔ کوچک است؛ حذف پایدار و شناسهٔ هرگز تکرارنشونده پس از حذف را الزام نکرده‌ایم.
اگر حذف اضافه کردی، دربارهٔ نگهداری NextId تصمیم بگیر.

## سناریوی تحویل

- سه درخواست ثبت و یکی را با دو انتقال به Closed ببر.
- یکی را rename کن و شناسه را ثابت نگه دار.
- restart کن؛ داده و وضعیت‌ها باید باقی باشند.
- فایل آزمایشی خراب را Load کن؛ بایت‌هایش ثابت بمانند.
- لغو پیش از Save را بررسی کن؛ مقصد تغییر نکند.
- وضعیت نامعتبر را رد کن و نشان بده مدل و فایل عوض نشده‌اند.

## دفاع از طراحی

برای هر سؤال دو تا پنج جمله با مثال از کد خودت بنویس:

- چرا Id را از index لیست نگرفتی؟
- چرا setter وضعیت عمومی نیست؟
- فرق null نتیجهٔ جست‌وجو و شکست Load چیست؟
- ToList چه چیزی را کپی می‌کند؟
- مالک بستن فایل یا source لغو کیست؟
- اگر Save شکست بخورد، state حافظه چه می‌شود؟
- چرا async الزاماً اجرای سریع‌تر یا thread تازه نیست؟
