# درس ۰۰۲ — نوع‌ها و اولین قابلیت SupportDesk

## خروجی درس

خلاصهٔ درخواست‌های باز و بسته را نمایش می‌دهی.
جمع و درصد تکمیل را محاسبه می‌کنی و خطای تقسیم صحیح را تشخیص می‌دهی.

## پیش‌نیاز

درس ۰۰۱ و اجرای موفق یک پروژهٔ کنسولی.
متغیر یک نام برای نگه‌داری مقدار است؛ مثلاً openTickets تعداد درخواست‌های باز را نگه می‌دارد. عملگرهایی مثل + و / هم روی این مقدارها محاسبه انجام می‌دهند. مثال‌های این درس را بدون دانش C++ دنبال کن.

## مسئله

تیم IT هشت درخواست باز و دو درخواست بسته دارد.
گزارش باید نام تیم، تعداد کل و درصد تکمیل را نشان بدهد.
در این مرحله داده ثابت است؛ ذخیره یا دریافت ورودی نداریم.

معیار پذیرش اولیه:

| مقدار | انتظار |
| --- | --- |
| باز ۸، بسته ۲ | کل ۱۰ و تکمیل ۲۰ درصد |
| باز ۰، بسته ۰ | کل ۰ و تکمیل ۰ درصد |
| باز ۰، بسته ۵ | کل ۵ و تکمیل ۱۰۰ درصد |

## ۱. انتخاب نوع

| نوع | کاربرد این نمونه | نکته |
| --- | --- | --- |
| string | نام تیم | متن است، عدد نیست |
| int | تعداد درخواست | اعداد صحیح در بازهٔ نوع |
| decimal | درصد | نمایش اعشاری پایهٔ ده |
| bool | در تمرین بعد: معتبر بودن | فقط true یا false |

نوع `int` برای عددهای صحیح، مانند تعداد درخواست‌هاست. این نوع ۳۲ بیت دارد و `signed` است؛ یعنی می‌تواند عدد منفی هم نگه دارد. البته قابلیت گزارش ما تعداد منفی را معتبر نمی‌داند؛ توانایی نوع داده با قانون برنامه یکی نیست.
decimal را برای همهٔ محاسبات به صورت خودکار انتخاب نکن؛ برای بسیاری از محاسبات علمی double مناسب‌تر است.
در محاسبات پولی نیز نوع به تنهایی کافی نیست: واحد و سیاست گرد کردن باید مشخص باشند.

نام متغیر باید معنی داده را روشن کند.
openTickets از x خواناتر است.
در نام‌گذاری `camelCase`، کلمهٔ اول با حرف کوچک و کلمه‌های بعدی با حرف بزرگ شروع می‌شوند؛ مثل `openTickets`. در `PascalCase` حرف اول همهٔ کلمه‌ها بزرگ است؛ مثل `TicketSummary`. در C# معمولاً اولی را برای متغیر محلی و دومی را برای کلاس و متد عمومی به کار می‌برند.

## ۲. دادهٔ اولیه

```csharp
string teamName = "IT Support";
int openTickets = 8;
int closedTickets = 2;
int totalTickets = openTickets + closedTickets;
```

علامت = انتساب است؛ برای مقایسهٔ برابری از == استفاده می‌کنیم.
رشته با کوتیشن دوتایی نوشته می‌شود.
تعدادها مستقل‌اند و totalTickets از آن‌ها محاسبه می‌شود.
اگر دادهٔ اولیه تغییر کند، مقدار کل باید دوباره محاسبه شود.

## ۳. خطای تقسیم صحیح

این کد را بررسی کن:

```csharp
int wrongPercentage = closedTickets / totalTickets * 100;
```

در این عبارت هر دو طرف تقسیم از نوع `int` هستند؛ پس نتیجهٔ تقسیم هم عدد صحیح است و بخش کسری نگه داشته نمی‌شود. با دو درخواست بسته از ده درخواست، نتیجهٔ مرحلهٔ اول صفر می‌شود، نه ۰٫۲. ضرب همین صفر در صد نیز صفر است. کد قابل کامپایل است، اما درصد غلطی می‌دهد؛ این همان خطای منطقی است.

این تبدیل دیرهنگام هم مشکل را حل نمی‌کند:

```csharp
decimal stillWrong = (decimal)(closedTickets / totalTickets) * 100m;
```

عمل داخل پرانتز پیش از تبدیل نوع یا `cast` اجرا می‌شود؛ بنابراین ابتدا بخش کسری از دست رفته و تبدیل صفر به `decimal` آن را برنمی‌گرداند. برای تقسیم اعشاری، حداقل یکی از دو مقدارِ طرف تقسیم، یعنی یکی از `operand`ها، باید پیش از تقسیم به نوع اعشاری تبدیل شود.

```csharp
decimal percentage = (decimal)closedTickets / totalTickets * 100m;
```

پسوند m یعنی literal از نوع decimal است.
cast روی closedTickets باعث می‌شود تقسیم در این عبارت اعشاری باشد.

## ۴. حالت صفر

در تیمی بدون درخواست، totalTickets صفر است.
تقسیم decimal بر صفر خطا ایجاد می‌کند.
برای این گزارش سیاست دامنه این است: اگر درخواستی نیست، درصد صفر نمایش بدهیم.

```csharp
decimal completionPercentage = totalTickets == 0
    ? 0m
    : (decimal)closedTickets / totalTickets * 100m;
```

عبارت `?:` یک `conditional operator` است: ابتدا شرطِ قبل از `?` بررسی می‌شود؛ اگر درست باشد مقدار بین `?` و `:` انتخاب می‌شود و اگر نادرست باشد مقدار پس از `:`. در این مثال، وقتی تعداد کل صفر است فقط `0m` انتخاب می‌شود. شاخهٔ تقسیم اصلاً اجرا نمی‌شود و خطای تقسیم بر صفر رخ نمی‌دهد.
در API واقعی ممکن است به جای صفر، وضعیت «داده‌ای نیست» نمایش دهیم؛ سیاست باید صریح باشد.

## ۵. نمایش متن

```csharp
Console.WriteLine($"Team: {teamName}");
Console.WriteLine($"Total: {totalTickets}");
```

علامت `$` پیش از متن، نوشتن مقدارها داخل `{...}` را ممکن می‌کند؛ این روش `string interpolation` نام دارد. برای مثال، در خط مربوط به تیم، مقدار `teamName` در جای آکولاد قرار می‌گیرد. در روش `concatenation` رشته‌ها را با عملی مثل `+` به هم وصل می‌کنیم؛ اینجا نوشتن قالب کامل پیام، محل هر مقدار را روشن‌تر می‌کند.

تنظیمات زبان و منطقهٔ سیستم یا `culture` بر نمایش عدد اثر می‌گذارد؛ مثلاً جداکنندهٔ اعشار ممکن است نقطه یا ویرگول باشد. برای اینکه خروجی این تمرین روی دستگاه‌های مختلف قابل مقایسه بماند، تنظیم نمایش را صریح انتخاب می‌کنیم.

```csharp
using System.Globalization;

Console.WriteLine(
    $"Completion: {completionPercentage.ToString("0.0", CultureInfo.InvariantCulture)}%");
```

0.0 در اینجا یک رقم اعشار نمایش می‌دهد.
InvariantCulture برای این نمونه جداکنندهٔ اعشار ثابت ایجاد می‌کند.
این انتخاب به معنی الزام به رابط انگلیسی در محصول نهایی نیست.

## ۷. آزمایش تغییر رفتار

نمونه را در exercises کپی کن تا فایل مرجع را دست‌نخورده داشته باشی.
مقدار باز و بسته را برای هر ردیف جدول پذیرش تغییر بده.
قبل از اجرا خروجی را پیش‌بینی کن.
برای باز ۲ و بسته ۱، انتظار نمایش 33.3 درصد داریم.
نمایش یک رقم اعشار مقدار اصلی محاسبه را تغییر نمی‌دهد.

در این نسخه تعداد منفی را دریافت نمی‌کنیم.
اگر در کد تعداد منفی بنویسی، دادهٔ دامنه نامعتبر ساخته‌ای؛ در درس بعد ورودی را بررسی می‌کنیم.

## ۸. var چه معنی دارد؟

```csharp
var count = 8;
var ratio = 20m;
```

کامپایلر از مقدار سمت راست تشخیص می‌دهد که `count` از نوع `int` و `ratio` از نوع `decimal` است؛ به این تشخیص، `type inference` می‌گویند. استفاده از `var` فقط نوشتن نام نوع را حذف می‌کند. متغیر همچنان نوع مشخص دارد و بعداً نمی‌توان هر نوع مقدار دلخواهی در آن گذاشت؛ با `dynamic` تفاوت دارد.
برای معرفی مفاهیم از نوع صریح استفاده کردیم تا انتخاب نوع دیده شود.
بعداً وقتی سمت راست نوع را واضح می‌کند، var می‌تواند خوانایی را حفظ کند.

## سرنخ

اول مبلغ پایه را حساب کن.
برای درصد، تقسیم بر 100m را پیش از ضرب نهایی در نظر بگیر.

اگر خروجی تخفیف برای ۱۰ درصد صفر شد، نوع operandهای تقسیم را بررسی کن.
