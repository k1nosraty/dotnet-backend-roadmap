# درس ۰۰۵ — متدها و جداسازی مسئولیت‌ها

[قبلی](../004-loops/README.md) · [خانه](../../../README.md) · [بعدی](../006-collections/README.md)

## خروجی درس

منوی درس قبل همچنان همان کار را انجام می‌دهد، اما کدش به متدهای مشخص تقسیم می‌شود: یکی عنوان را می‌گیرد، یکی اعتبار آن را می‌سنجد و دیگری نتیجه را چاپ می‌کند. با دنبال‌کردن ورودی و خروجی هر متد می‌بینی چرا تغییر پیام کنسول نباید قانون عنوان را عوض کند. این جداسازی در نسخهٔ وب هم به کار خواهد آمد.

## پیش‌نیاز

درس ۰۰۴، حلقه، switch و return.
در این درس کد هنوز یک فایل است؛ ساخت کلاس در درس ۰۰۷ معرفی می‌شود.

## ۱. مسئلهٔ کد قبلی

بخش ثبت هم پیام کنسول را چاپ می‌کند، هم ورودی می‌خواند، هم عنوان را بررسی می‌کند.
اگر پیام را تغییر دهیم، به همان بخش قانون طول دست می‌زنیم.
اگر بخواهیم قانون عنوان را روی فایل یا HTTP اجرا کنیم، نباید مجبور به خواندن Console باشیم.
هدف این درس دیدن مرز مسئولیت است؛ صرفاً کوتاه کردن فایل هدف کافی نیست.

## ۲. تعریف یک متد با ورودی و خروجی

در فایل `Program.cs` می‌توان تابعی تعریف کرد که همان‌جا استفاده شود؛ به آن `local function` می‌گویند. در قطعهٔ زیر، ورودی تابع یک عنوان و خروجی آن پاسخ درست یا نادرست است. خط تعریف تابع، شامل نام، نوع خروجی و پارامترها، `signature` آن را نشان می‌دهد:

```csharp
static bool IsValidTitle(string title)
{
    return title.Length >= 3 && title.Length <= 120;
}
```

| بخش signature | معنی |
| --- | --- |
| static | تابع به متغیرهای محلی بیرون خودش دسترسی ضمنی ندارد؛ دادهٔ لازم را باید از پارامتر بگیرد. این دسترسی ضمنی را `capture` می‌نامند. |
| bool | نوع مقدار بازگشتی |
| IsValidTitle | نام عملیات |
| string title | پارامتر ورودی |

در این قرارداد title نباید null باشد و باید قبلاً Trim شده باشد.
nullable annotation تحلیل کامپایلر است؛ خودکار جلوی همهٔ nullهای runtime را نمی‌گیرد.
توضیح قرارداد در کنار تابع لازم است.

## ۳. فراخوانی و argument

```csharp
bool accepted = IsValidTitle("Network issue");
```

نام `title` در تعریف تابع یک `parameter` است؛ یعنی جایی که ورودی تابع قرار می‌گیرد. متن `"Network issue"` مقداری است که هنگام فراخوانی به آن می‌دهیم و `argument` نام دارد. تابع عنوان را بررسی می‌کند و با `return` پاسخ را به کد فراخواننده می‌دهد؛ این پاسخ در `accepted` قرار می‌گیرد.

در نمونهٔ بالا، return فقط IsValidTitle را تمام می‌کند.
در Program اصلی، return top-level جریان برنامه را تمام می‌کند.
پس محل return تعیین‌کننده است.

## ۴. چرا این تابع نسبتاً خالص است؟

این تابع برای یک عنوان مشخص همیشه همان پاسخ `bool` را می‌دهد. در کنسول چیزی نمی‌نویسد، فایل را تغییر نمی‌دهد و مقدار بیرونی را هم عوض نمی‌کند. تابع با چنین رفتاری را `pure function` می‌نامند. می‌توانی آن را مستقیماً با یک عنوان صدا بزنی و نتیجه را بررسی کنی، بدون اینکه لازم باشد منو یا دریافت ورودی را اجرا کنی.
«خالص» بودن به معنی درست بودن قانون نیست؛ ممکن است یک تابع خالص قانون اشتباهی داشته باشد.

مثلاً اگر >= 3 را به > 3 تبدیل کنیم، عنوان سه‌کاراکتری اشتباه رد می‌شود.
تست boundary همچنان لازم است.

## ۵. تابع void

```csharp
static void PrintCount(int count)
{
    Console.WriteLine($"Registered count: {count}");
}
```

نوع خروجی `void` یعنی متد مقداری برای انتساب به یک متغیر برنمی‌گرداند. بااین‌حال، متد بی‌اثر نیست: روی کنسول می‌نویسد. این تغییر بیرون از مقدار خروجی، `side effect` نام دارد. مقدار لازم را از پارامتر `count` می‌گیرد؛ پس لازم نیست به نام و محل متغیر `registeredTickets` در منو وابسته باشد.

```csharp
PrintCount(registeredTickets);
```

فرستادن مقدار روشن‌تر از پنهان کردن dependency روی متغیر بیرونی است.
در آینده همین ایده برای وابستگی‌های service به کار می‌رود.

## ۶. دریافت عنوان با خروجی قابل بررسی

```csharp
static string? ReadTitle()
{
    while (true)
    {
        Console.Write("Title (3-120 characters): ");
        string? rawTitle = Console.ReadLine();
        if (rawTitle is null)
        {
            return null;
        }
        string title = rawTitle.Trim();
        if (IsValidTitle(title))
        {
            return title;
        }
        Console.WriteLine("Invalid title. Try again.");
    }
}
```

این متد مسئول تعامل با کاربر است.
عنوان معتبر را برمی‌گرداند و پایان ورودی را با null اعلام می‌کند.
ورودی خراب با تکرار دریافت مدیریت می‌شود.
نباید null را اینجا به عنوان معتبر خالی تبدیل کنیم.

## ۷. فراخواننده مسئول تصمیم بعدی است

```csharp
string? title = ReadTitle();
if (title is null)
{
    Console.WriteLine("Input ended.");
    return;
}
registeredTickets++;
Console.WriteLine($"Registered: {title}");
```

متد ReadTitle هیچ شمارنده‌ای را تغییر نمی‌دهد.
فراخواننده فقط پس از موفقیت شمارنده را زیاد می‌کند.
این جداسازی جلوی تکرار محاسبه در هر تلاش ناموفق را می‌گیرد.
قانون ورودی و تصمیم ثبت دو مسئولیت متفاوت‌اند.

## ۸. scope و طول عمر متغیر

محدوده‌ای که در آن نام یک متغیر قابل استفاده است، `scope` نام دارد. متغیر `title` داخل `ReadTitle` را نمی‌توان از بیرون آن متد خواند؛ در مقابل، شمارنده در محدودهٔ اجرای منو نگه داشته می‌شود. یکسان‌بودن نام دو متغیر در دو محدوده به معنی مشترک‌بودن مقدارشان نیست.

```csharp
static int Increase(int count)
{
    return count + 1;
}
```

تابع `Increase` یک کپی از مقدار `int` را می‌گیرد؛ به این روش `pass by value` می‌گویند. جمع‌کردن داخل تابع، متغیر اصلی منو را تغییر نمی‌دهد. برای نگه‌داشتن نتیجه باید مقدار بازگشتی را دوباره در همان متغیر قرار بدهی:

```csharp
registeredTickets = Increase(registeredTickets);
```

در نمونهٔ مرجع چنین تابعی اضافه نشده، چون افزایش ساده به abstraction جدید نیاز ندارد.
این مثال فقط معنی ورودی و خروجی را نشان می‌دهد.

## ۹. استخراج تابع با حفظ رفتار

بازآرایی یعنی ساختار را تغییر دهیم و رفتار مورد انتظار را حفظ کنیم.
ابتدا جدول پذیرش درس ۰۰۴ را دوباره اجرا کن.
سپس قانون را به IsValidTitle منتقل کن.
بعد دریافت را به ReadTitle منتقل کن.
بعد چاپ منو و گزارش را جدا کن.
بعد از هر انتقال سناریوها را بررسی کن.
هم‌زمان تغییر دادن قواعد و ساختار تشخیص علت شکست را سخت می‌کند.

## ۱۱. نقشهٔ مسئولیت فعلی و آینده

| امروز | مسئولیت | مقصد محتمل در نسخهٔ وب |
| --- | --- | --- |
| ShowMenu / ReadTitle | تعامل با کاربر | endpoint و binding |
| IsValidTitle | قانون شکل عنوان | validation ورودی |
| شمارنده در Program | state و هماهنگی | application service و storage |
| PrintCount | نمایش نتیجه | response DTO و HTTP response |

این جدول حکم تبدیل مستقیم همهٔ توابع به کلاس نیست.
بعضی قواعد به domain تعلق خواهند داشت؛ بررسی مالکیت و ذخیره نیز بعداً اضافه می‌شود.
تصمیم با پیچیدگی واقعی رشد می‌کند.

## تمرین اصلی

تمرین هزینهٔ درس ۰۰۳ را با سه مسئولیت جدا بازنویسی کن:

1. دریافت و اعتبارسنجی ساعت و نرخ و تخفیف.
2. محاسبهٔ مبلغ نهایی با تابعی بدون Console.
3. نمایش نتیجه همراه واحد تومان.

امضای پیشنهادی تابع محاسبه:

```csharp
static decimal CalculateFinalCost(decimal hours, decimal hourlyRate, decimal discountPercent)
```

در این مرحله قرارداد تابع: ورودی‌ها باید قبلاً در بازهٔ مجاز درس ۰۰۳ بررسی شوند.
در درس exception بررسی دفاعی قرارداد را یاد می‌گیریم.
برای پول بعداً سیاست rounding هم لازم است؛ مثال فعلی به گرد کردن نیاز ندارد.

## سرنخ

اول تابع محاسبه را فقط با مقادیر ثابت صدا بزن.
وقتی نتیجه درست بود، دریافت ورودی را به آن متصل کن.
به جای ref برای تغییر متغیر، بازگرداندن نتیجه را ابتدا بررسی کن.
در این مرحله نیازی به delegate یا کلاس static عمومی نیست.
