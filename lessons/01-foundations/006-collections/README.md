# درس ۰۰۶ — List، Dictionary و جست‌وجوی درخواست‌ها

[قبلی](../005-methods/README.md) · [خانه](../../../README.md)

## خروجی درس

چند عنوان درخواست در حافظه نگه می‌داری، شناسه می‌دهی، فهرست می‌کنی و با شناسه جست‌وجو یا حذف می‌کنی.
تفاوت ترتیب یک لیست و lookup بر اساس کلید را توضیح می‌دهی.
تاریخچهٔ عملیات را در یک List جدا ثبت می‌کنی.

## پیش‌نیاز

درس ۰۰۵، تابع، حلقه و int.TryParse با همان الگوی TryParse درس ۰۰۳.
کلاس Ticket هنوز تعریف نشده است؛ در این مرحله مقدار هر درخواست فقط عنوان است.
در درس بعد همین مدل کوچک به کلاس دارای property تبدیل می‌شود.

## ۱. چرا شمارنده کافی نیست؟

شمارنده می‌گوید چند درخواست ثبت شد، اما نمی‌گوید عنوان درخواست ۲ چه بوده است.
برای پاسخ دادن به این سؤال باید دادهٔ هر درخواست را نگه داریم.
مجموعهٔ داخل حافظه با پایان برنامه از بین می‌رود.
این درس هنوز دیتابیس یا ذخیرهٔ پایدار نیست.

## ۲. آرایه و List

```csharp
string[] fixedTitles = { "Network issue", "Printer issue" };
List<string> titles = new();
titles.Add("Network issue");
titles.Add("Printer issue");
```

آرایه طول ثابتی دارد؛ می‌توان مقدار عنصرهایش را تغییر داد.
List برای افزودن و حذف از یک توالی مناسب است.
داخل <> نوع عنصر مشخص می‌شود.
List<string> فقط مقدارهای سازگار با string را می‌پذیرد.
این generic بودن به معنی بی‌نوعی نیست.
new() نوع را از سمت چپ می‌گیرد؛ همان new List<string>() است.

## ۳. index و Count

```csharp
Console.WriteLine(titles.Count);
Console.WriteLine(titles[0]);
```

index از صفر شروع می‌شود.
با دو عنصر، indexهای معتبر ۰ و ۱ هستند.
Count برابر تعداد عنصرهای فعلی است؛ با ظرفیت داخلی یکی نیست.
index نامعتبر exception ایجاد می‌کند.
قبل از انتخاب کاربر باید محدوده بررسی شود.

## ۴. index شناسهٔ پایدار نیست

فرض کن سه عنوان در indexهای ۰، ۱ و ۲ داریم.
با حذف عنصر اول، عنصرهای بعدی به جلو جابه‌جا می‌شوند.
پس «عنصر شمارهٔ ۱» بعد از حذف ممکن است درخواست متفاوتی باشد.
برای شناسهٔ درخواست از موقعیت لیست استفاده نمی‌کنیم.
شناسه باید در همان اجرای برنامه مستقل از محل نمایش باشد.

## ۵. foreach

```csharp
foreach (string title in titles)
{
    Console.WriteLine(title);
}
```

به ترتیب عنصرهای List را می‌خواند.
برای صرفاً پیمایش، index لازم نیست.
در حین foreach روی List، با Add یا Remove ساختار همان لیست را تغییر نده.
این کار معمولاً enumeration را نامعتبر می‌کند.
اگر حذف گروهی لازم است، راه‌های مشخصی مانند پیمایش معکوس با for وجود دارد.

```csharp
for (int i = titles.Count - 1; i >= 0; i--)
{
    if (titles[i].Length < 3)
    {
        titles.RemoveAt(i);
    }
}
```

پیمایش معکوس اجازه می‌دهد حذف عنصرهای بعدی، index عنصرهای هنوز بررسی‌نشده را جابه‌جا نکند.
این یک مثال مستقل است؛ در منوی مرجع از این حذف گروهی استفاده نشده است.

## ۶. Dictionary

```csharp
Dictionary<int, string> titlesById = new();
titlesById.Add(1, "Network issue");
titlesById.Add(2, "Printer issue");
```

نوع اول int کلید است؛ نوع دوم string مقدار است.
هر کلید فقط یک مقدار دارد.
دو درخواست می‌توانند عنوان یکسان و کلید متفاوت داشته باشند.
Add با کلید تکراری خطا ایجاد می‌کند.
به همین دلیل تولید شناسه مستقل از عنوان انجام می‌شود.

## ۷. indexer و TryGetValue

```csharp
titlesById[1] = "Updated network issue";
```

انتساب با indexer مقدار کلید موجود را تغییر می‌دهد؛ اگر کلید وجود نداشته باشد آن را اضافه می‌کند.
برای ثبت درخواست تازه، Add کمک می‌کند برخورد کلید پنهان نماند.
خواندن مستقیم titlesById[99] در نبود کلید خطا می‌دهد.
برای شناسهٔ کاربر وجود کلید قطعی نیست:

```csharp
if (titlesById.TryGetValue(99, out string? title))
{
    Console.WriteLine(title);
}
else
{
    Console.WriteLine("Ticket not found.");
}
```

bool نتیجه تعیین می‌کند مقدار واقعاً پیدا شده یا نه.
کلید ناموجود یک نتیجهٔ عادی جست‌وجو است، نه دلیل crash.

## ۸. ساخت شناسه

```csharp
int id = nextId;
titlesById.Add(id, title);
nextId++;
```

nextId باید بیرون حلقهٔ منو مقدار اولیهٔ ۱ بگیرد.
برای این نمونه تک‌نخی، بعد از ثبت موفق افزایش می‌یابد.
حذف درخواست nextId را عقب نمی‌برد.
از Count + 1 استفاده نکن؛ بعد از حذف یک رکورد ممکن است با کلید موجود برخورد کند.

نمونه قبل از رسیدن nextId به int.MaxValue ثبت را متوقف می‌کند تا overflow رخ ندهد.
برای وب‌سرویس چنددرخواستی، این روش generator مشترک امن نیست.
بعداً تولید شناسه در دیتابیس یا روش مناسب دیگر را بررسی می‌کنیم.

## ۹. حذف و اثرش روی گزارش

```csharp
bool removed = titlesById.Remove(id);
```

true یعنی کلید وجود داشته و حذف شده است.
false یعنی چیزی برای حذف وجود نداشته است.
گزارش تعداد فعلی از titlesById.Count گرفته می‌شود.
شمارندهٔ «کل ثبت‌های انجام‌شده» با «درخواست‌های فعلی» یکی نیست.
تاریخچهٔ فعالیت می‌تواند ثبت حذف را نگه دارد، حتی وقتی خود درخواست حذف شده است.

## ۱۰. تاریخچه در List

```csharp
List<string> activity = new();
activity.Add("Added #1");
activity.Add("Deleted #1");
```

این توالی ترتیب فعالیت‌های این اجرای برنامه را نگه می‌دارد.
Dictionary دادهٔ فعلی درخواست‌هاست و List پیام‌های تاریخچه است.
این دو کپی کامل از یک دیتاست نیستند و کاربردشان متفاوت است.
این history آموزشی، audit log امنیتی قابل اتکا نیست؛ با پایان برنامه پاک می‌شود و هویت و زمان ندارد.

## ۱۱. ترتیب Dictionary

برای نمایش مرجع، روی KeyValuePair پیمایش می‌کنیم:

```csharp
foreach (KeyValuePair<int, string> ticket in titlesById)
{
    Console.WriteLine($"#{ticket.Key}: {ticket.Value}");
}
```

به ترتیب داخلی Dictionary به عنوان قرارداد نمایش تکیه نکن.
اگر نیازمندی ترتیب بر اساس شناسه است، باید مرتب‌سازی صریح انجام شود.
در درس LINQ مرتب‌سازی و pagination را بررسی می‌کنیم.
تست این درس وجود رکوردها را بررسی می‌کند و به ترتیب Dictionary وابسته نیست.

## ۱۲. انتخاب ساختار

| نیاز | انتخاب اولیه | دلیل |
| --- | --- | --- |
| تاریخچه به ترتیب اضافه شدن | List<string> | توالی مهم است |
| پیدا کردن عنوان با شناسه | Dictionary<int, string> | lookup با کلید |
| دو عنوان ثابت برای مثال | array | طول ثابت است |

جست‌وجوی ساده در List معمولاً عنصرها را بررسی می‌کند.
Dictionary lookup میانگین سریع‌تری بر اساس hash دارد، اما بدون هزینهٔ حافظه یا بدترین حالت نیست.
برای مجموعهٔ کوچک، خوانایی و معنی داده را هم لحاظ کن.
نوع collection به تنهایی نیاز به profiling یا طراحی دیتابیس را حذف نمی‌کند.

## ۱۵. مرز طراحی این مرحله

Dictionary<int, string> نمی‌تواند وضعیت و اولویت یک Ticket را مدل کند.
ساخت چند dictionary موازی برای عنوان و وضعیت و اولویت خطر ناسازگاری دارد.
در درس بعد، مقدار dictionary را به یک کلاس Ticket تبدیل می‌کنیم.
فعلاً مفهوم کلاس را با چند property استفاده‌نشده جلوتر نمی‌آوریم.

## تمرین مستقل

گزینهٔ ۶ را برای تغییر عنوان با شناسه اضافه کن.
شناسهٔ ناموجود نباید رکورد تازه ایجاد کند.
عنوان تازه باید همان اعتبارسنجی عنوان ثبت را داشته باشد.
پس از تغییر موفق، فعالیت `Renamed #id` ثبت شود.
شناسه ثابت بماند و nextId عوض نشود.

## تمرین تکمیلی

نمایش تاریخچه را به ده مورد آخر محدود کن.
این محدودیت فقط نمایش است؛ حذف دادهٔ قدیمی را با محدودیت نمایش اشتباه نگیر.
از for و Count استفاده کن و برای تاریخچهٔ کمتر از ده، index منفی نساز.

## سرنخ

برای rename، اول TryGetValue یا ContainsKey را بررسی کن و سپس assignment انجام بده.
برای ده مورد آخر، شروع پیمایش باید حداقل صفر باشد.
خطای «کلید ناموجود» و «عنوان نامعتبر» دو مسیر جدا دارند.

## معیار عبور

- [ ] index و شناسه را یکی نمی‌گیرم.
- [ ] حذف رکورد باعث برخورد شناسهٔ تازه نمی‌شود.
- [ ] تفاوت Add و assignment با indexer را توضیح می‌دهم.
- [ ] شناسهٔ ناموجود بدون exception مدیریت می‌شود.
- [ ] حین foreach روی List از همان لیست حذف نمی‌کنم.
- [ ] rename رکورد تازه نمی‌سازد و فعالیت ناموفق ثبت نمی‌کند.
- [ ] محدودیت حافظه و ناپایداری دادهٔ این نسخه را می‌دانم.
