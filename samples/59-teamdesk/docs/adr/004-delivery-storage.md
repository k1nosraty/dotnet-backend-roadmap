# ADR 004 — storage آزمایشی و تحویل معماری

## وضعیت
پذیرفته‌شده برای نسخهٔ آموزشی تک‌فرایندی؛ محصول production نیست.

## زمینه
برای بررسی معماری و restart روی Windows و Linux، باید اجرا بدون تنظیم دیتابیس هم ممکن باشد. API پایدار PostgreSQL درس ۴۸ قبلاً integration مستقل دارد.

## تصمیم
پیش‌فرض host حافظه است. فقط نمونهٔ تحویل ۶۰ با TEAMDESK_DATA از فایل JSON اختصاصی نسخهٔ ۲ استفاده می‌کند. NextId مستقل از شناسه‌های موجود ذخیره می‌شود تا حذف باعث استفادهٔ مجدد از شناسه نشود. چند instance در یک process و path یکسان هماهنگ می‌شوند.

## جایگزین‌ها
PostgreSQL برای هماهنگی چند process مناسب‌تر است ولی adapter آن باید با portها و transaction و migration درست یکپارچه شود. lock فایل یا پوشهٔ مشترک به‌تنهایی تضمین چند server نیست.

## پیامدها
این adapter قفل distributed، تضمین قطع برق و migration خودکار از فایل درس ۵۴ ندارد. فایل نسخهٔ نامعتبر یا خراب رد می‌شود و با seed جایگزین نمی‌شود. مسیر داده از تنظیمات مورد اعتماد host می‌آید، نه request مشتری.

## شاهد و بازنگری
تست restart، شناسه پس از حذف، درخواست هم‌زمان و حفظ فایل خراب در scripts/architecture_final_smoke.py. فایل تازه برای این نمونه بساز. پیش از استفادهٔ چندکاربره، persistence واقعی و فصل امنیت باید تحویل شوند.

در Windows، تعویض فایل در صورت خطای sharing/lock به‌صورت محدود تا ۵۰۰ میلی‌ثانیه دوباره امتحان می‌شود؛ خطاهای دیگر یا قفل طولانی همچنان شکست می‌خورند و فایل اصلی حفظ می‌شود. این رفتار جایگزین هماهنگی بین چند process نیست.
